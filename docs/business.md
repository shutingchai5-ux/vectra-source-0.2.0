# 企业经营台账与联合指标

企业在统一入口使用本公司账号登录后打开“私有经营台账”。四个页签分别保存独立台账，草稿跨页签保留；离开前会提示未保存。新数据先“加入本方草稿”，再“保存本方台账与资料范围”；导入 JSON 只追加草稿，保存时服务端进行完整校验。

## 一致规则

台账每类每公司最多6000条，四个固定入口、上海时间。每条 id 在本台账唯一。未来记录以整点或半点为计划起点，最多未来31天；已开始记录只读，结束后可从当前引用归档，旧版本保留。装载事实必须已经离园，不能填未来事实。更正生成新版本，旧报告继续绑定原版本。

“本方资料已完整核对的时间范围”是公司声明：声明覆盖每个查询分组时记为一家资料齐全。空台账加完整声明可以表达明确为零；未声明、未覆盖或可选字段缺失不会自动补零。声明只说明企业提供的资料范围，不证明未虚报或漏报，也不构成隐私发布门槛。

历史版本选择器列出最近50版，只能读取本公司。JSON 可使用记录数组或包含 records 的对象，时间可写 Unix 毫秒或带上海偏移的 ISO 时间。数组中不能混入其他公司归属、未知字段、可执行表达式或原始客户订单。

## 运输需求与到达弹性（demand）

每条表示一份本公司已合并去重的运输需求及其到达窗口；系统不把订单自动换算成车次。

| 字段 | 含义 |
|---|---|
| id、road、slotStart | 记录编号、入口、计划到达时段 |
| earliestAt、latestAt | 最早、最晚允许到达，计划时段必须位于其间 |
| expectedTrips、reservedTrips | 总需求车次、其中已预约车次 |
| minimumCommittedTrips | 当前至少保留的需求车次，不得超过总需求 |
| expectedWorkMinutes | 总需求对应作业分钟；有需求须大于零 |
| cargoTonnes、cargoVolumeM3、pallets | 可选预计吨数、体积、托盘，未知留空 |

本地派生未预约数＝总需求－已预约；存在可调整窗口时，可调整数＝总需求－最低保留。可提前、可延后分别观察窗口与计划时段，同一需求可能同时具备二者，不可相加。按计划到达选择为默认口径，也支持按最晚到达选择。每条只归入一个开始时段，不在所有可选窗口中重复计数。“两小时内到期”以查询起点为固定基准。

结果用于决定是否协商预约、延长接纳窗口或增配作业资源；不会修改预约或自动生成每家公司获配量。

## 实际装载与空驶（haulage）

先在车辆与车次中确认离园，再选择本方已完成车次。visitId 和 sourceParkVersion 固定来源，入口、车辆和离园时间从来源复制，不能在经营台账伪造新车次。

| 可选字段 | 统计意义 |
|---|---|
| actualLoadTonnes、loadCapacityTonnes | 同一车次实际吨数及适用载重；可从车辆档案带入额定载重并核对 |
| actualVolumeM3、loadCapacityVolumeM3 | 同车次实际体积和适用容积 |
| pallets、loadCapacityPallets | 同车次托盘数和可用托盘容量 |
| loadedDistanceKm、emptyDistanceKm | 载货与空驶里程须成对提供；已有车次总里程时，二者之和必须相符 |

加权利用率＝同批有效实际装载总和／同批适用容量总和。重量、体积和托盘分别计算；容量为零不产生有效利用率。联合空驶率＝同批空驶里程总和／同批载货与空驶总里程。低装载比例可指定受控阈值，默认分析模板使用低于50%；分母只包含有有效利用率的记录，不能把未知容量当低装载。

吨公里是实际吨数乘载货里程的参考量，仅适用于整段载货里程使用同一载货量；它不是自动还原的多段装卸事实。装载统计按离园时间选取，不与入口到达批次混用。

## 回程运力（returns）

id、road、slotStart、availableUntil、availableTrips、regionCode 分别表示编号、入口、开始、有效截止、可承接车次额度和粗区域。

粗区域固定为1园区周边、2华东、3华北、4华南、5华中、6西南、7西北、8东北、9其他。可以按一个粗区域筛选联合车次总量。按申报开始时间选取，每条只计一次；不公开具体客户、订单、车辆或精细路线，不实施逐订单匹配。企业应自行核对同一真实运力是否重复承诺。

## 分时充电需求（charging）

本公司已建档车辆才能申报，包含 id、road、vehicleId、slotStart、deadlineAt、connector、batteryCapacityKwh、socPercent、targetSocPercent，maxPowerKw 可选。connector 为 dc、ac、other。目标电量须高于当前电量且不超过100%；同一车辆时间窗不能重叠。

所需电量＝电池容量×（目标电量百分比－当前电量百分比）／100，在本企业服务内派生。联合输出仅包含所需电量、接口分类、紧迫请求及已知最大功率下仍无法在允许窗口完成的请求数量。紧迫截止为查询起点后两小时。未知车辆功率不视为零，也不能把“未判定无法完成”解释成“一定可完成”。

园区在“联合运营分析 → 私有经营数据联合分析 → 分时充电”维护每半小时、每入口、每接口的数量、单接口功率和分配电量，电量不能高于数量×功率×0.5小时。零表示明确不提供，未配置表示未知。资料声明三家齐全、查询分组边界为完整半小时且各容量时段齐全，才计算电量缺口。需求按预计到达起点计入分组，表示该批请求的电量压力；没有把每辆车的充电量安排到具体桩或截止前各时段，不能据此断言排程可行。

## 模型、协议与报告

模型只能选择经过校验的字段、操作和阈值，不能上传代码、SQL 或直接读取企业台账。各节点本地派生后分享充分统计量，恢复批准的联合指标；计数、总和、均值、方差、标准差、阈值比例及总和比值可组合，单次不能跨台账做任意关联。

对话与报告统一显示经营类型、计划/实绩、时间范围、各分组声明覆盖、贡献方和有效记录。资料不足时限定为已收到资料；原始经营记录不进入园区材料页或 LLM，Git 日志对 records、车辆标识、SOC、装载与里程等字段脱敏。企业自行键入对话的其他业务文本仍属于对话正文，不自动获得结构化台账的保护。

本批实现 A/B/C/D/G 的联合聚合与回程粗区域额度。分类专用运力、专用资源、成本、履约异常、隐私关联、隐藏中间量的比较/分配和自动排程见[后续规划](carrier-private-data-plan.md)。
