# 承运商经营信息的秘密共享保护规划

规划日期：2026-11-02（Asia/Shanghai）。状态：第一批 A/B/C/D/G 聚合能力已实现；E/F/H/I/J、私密分配与更强协议仍为后续设计。实现细节见[经营台账说明](business.md)与[独立部署](deployment.md)。

## 1. 目标与适用条件

在现有车次、预约需求、运力和完整行程能耗之外，引入承运商不愿向园区或其他承运商公开的经营信息。各方保留本地明细，按共同业务口径计算，交换秘密份额，只恢复事先批准的联合结果。

优先选择同时满足以下条件的信息：存在多家独立数据持有者；单家企业的汇总值本身也敏感；联合结果能改变预约、资源配置或运营复核决策；允许公开的结果足以支持决策。

如果企业愿意直接向可信平台提供本地统计量，普通汇总也可以满足需要。敏感但没有联合计算用途的字段不应仅为使用协议而收集。

Shamir 秘密共享是按门限拆分秘密的机制。本系统利用份额可加性构成联合聚合；比较、排序、匹配与优化还需要对应的多方计算协议。业务价值与优先级是基于当前园区场景提出的设计判断。

## 2. 当前基础与缺口

| 信息域 | 当前代码已有 | 仍需新增或明确 |
|---|---|---|

## 3. 候选保护信息

| 编号 | 建议保护的信息与本地字段示例 | 为什么敏感 | 批准的联合输出与业务用途 | 实施判断 |
|---|---|---|---|---|
| A | 未预约运输需求：本地运输任务、最早可到达时间、最晚到达期限、货量；本地派生 `unreservedTrips`、`dueSoonTrips` | 可反映客户订单积压、经营规模和交付压力 | 各时段未预约需求、紧迫需求及预计作业量，决定是否开放预约额度和增加作业班次 | 优先；新增需求台账与统一时间口径，采用本地分类和安全聚合 |
| B | 到达弹性：允许提前或延后范围、可调整车次、最低保留承诺；本地派生 `flexibleTrips`、`advanceableTrips`、`delayableTrips` | 反映企业调度余量与履约约束 | 可错峰需求总量、各后续时段可承接总量，辅助预约协商 | 优先统计；自动生成私密逐方分配需要更强协议 |
| C | 真实装载：`actualLoadTonnes`、`actualVolumeM3`、托盘数，以及同批车次适用运载能力 | 反映客户出货规模、载货效率与企业运输组织能力 | 同口径货运量、装载利用率、低装载车次比例，评估车辆与预约资源使用情况 | 优先；车辆档案中的额定载重不能替代这些事实 |
| D | 空驶与回程：`loadedDistanceKm`、`emptyDistanceKm`、可承接回程的时段与粗区域 | 反映线路效率、客户布局及可利用的业务机会 | 联合空驶率、可利用回程运力规模，判断是否值得开展回程协同 | 空驶聚合优先；逐任务匹配另行设计，不上传精细轨迹 |
| E | 可兑现的分类运力：车型、动力、资质匹配情况、可执行时间；本地派生 `qualifiedAvailableTrips`、`maintenanceUnavailableTrips` | 反映实际车队实力、司机排班和经营保障能力 | 按公开分类汇总可承诺车次和短缺，识别冷藏、大件等业务是否有足够能力 | 需新增分类目录和本地资源去重；不用司机身份或健康信息充当共享输入 |
| F | 专用作业资源需求：月台、叉车、吊装或冷链资源的类型、需求分钟、兼容要求 | 可能反推出货物构成和客户服务要求 | 各时段各资源需求与容量缺口，决定作业位、设备和人员安排 | 高价值；现有总作业分钟不能表示不同资源之间的可替代性 |
| G | 充电与能源需求：本地电池剩余电量、行程需要、电池与接口能力；派生 `requiredChargeKwh` 和需求时限 | 反映车辆续航余量、路线计划和运力限制 | 分时段补能总量、相容接口需求及紧迫车次数，安排充电设施与接驳资源 | 优先汇总；总电量满足不代表逐车充电一定可排程 |
| H | 运输与等待成本：本车次能源费、路桥费、人工成本、等待损失估算及模型版本 | 可反映成本结构、利润空间和经营效率 | 授权范围内的历史联合成本、单位运输成本与等待损失，量化运营改善价值 | 第二批；不共享客户合同价、单家底价或未经授权的精确成本 |
| I | 履约与异常：已承诺任务、实际兑现、取消、临时换车、故障、延迟及粗原因码 | 反映企业履约能力与运营薄弱环节 | 同一承诺批次的兑现率、取消率和异常率，支持高峰资源缓冲与预约规则复核 | 第二批；冻结原承诺版本并与本方事实关联，不能用两个无关时段总数相除 |
| J | 货损与温控服务质量：适用运输任务数、异常任务数、货损数量、温控异常时长 | 涉及客户服务表现、索赔和运输品质 | 相同业务与判定规则下的异常率、异常时长分布，评估设施和交接改进 | 仅在实际业务存在且取得相应数据使用授权时实施；不把缺少传感器记录视为正常 |

客户名称、联系人、完整订单、合同正文、精细轨迹、司机身份证等可以留在企业业务系统作为来源依据；默认不进入联合统计协议、模型上下文或Git诊断日志。

## 4. 各信息域的计算口径

### 4.1 未预约需求与可调整需求

本地先按明确规则把运输任务换算为可执行车次。订单数、货物件数、车辆数、车次额度是不同对象，不能直接互换。尚未确定的需求与已确认承诺分开统计。

同一可调整车次可能可以移到多个时间窗，但不能在联合可调整总量中重复相加。第一版只展示去重后的可调整规模；需要逐时段调整方案时，每个候选方案必须对原任务或运力预算只占用一次。

### 4.2 装载与空驶

以有效车次为共同样本，在承运商本地派生实际货量、适用运载能力、载货里程、空驶里程和吨公里。只分享必要的可加统计量。

按车次额定载重归一化的装载利用率：

$$
U = \frac{\sum \text{实际载货吨数}}{\sum \text{同批车次适用额定载重吨数}} \times 100\%
$$

这是按适用额定载重加权的车次装载指标；若目标是整段行程运输效率，应另用吨公里与对应可用运力里程计算。重量、体积和托盘指标分别计算，不混合单位。

联合空驶率：

$$
R_{\mathrm{empty}} = \frac{\sum \text{空驶里程}}{\sum (\text{载货里程}+\text{空驶里程})} \times 100\%
$$

上述分子和分母必须使用同批完整有效记录，不能把不同样本的总量拼成比例，也不能把各企业比例直接平均。

### 4.3 司机与分类运力

企业在本地依据其业务规则评估可承担车次、适用车型和资质。联合协议接收通过本地校验的统计量，不接收司机个人身份明细。司机人数、车辆数与运输车次额度分别定义。

同一车辆、司机或设备在重叠时段不能重复承诺；仅对申报额度求和不能自动证明承诺可兑现。需要本地资源占用校验和承诺凭证。

### 4.4 专用资源与充电

月台分钟、叉车分钟、吊装分钟、冷链库位等分别维护资源类别、单位、容量和兼容规则。不能把不同资源分钟相加后据此断言能够接纳。

充电统计优先使用本地派生的需求电量与时限；单车荷电状态、精细路线和电池标识不公开。园区充电资源作为独立的公开或授权容量上下文，与任务版本绑定。

分时总电量与可供电量比较只是一项容量检查；还需考虑到达、截止时间、接口、功率和并行占用，才能形成可执行排程。

### 4.5 经营成本、履约与服务质量

费用按明确的成本口径和固定版本记录，优先采用整数分；估算损失与实际支付费用分开。若使用吨公里作为分母，在企业本地对同车次载货量与里程计算乘积，再联合求和。

$$
\text{单位运输成本} = \frac{\sum \text{同批有效车次成本}}{\sum \text{同批有效车次吨公里}}
$$

兑现率等指标应绑定原始承诺批次，明确部分完成、取消、补录和跨日任务的处理。异常需要统一判定标准与完整分母，不能由LLM自行把文字原因推定为已验证事实。

现有完整行程电耗不等于园区内能耗、等待电耗或碳排放。增加分阶段能耗必须有对应计量来源；增加碳结果应另行确定核算边界及因子版本。

## 5. 信息放在哪里

建议按业务对象组织私有台账，不把全部字段塞入车辆档案或每条车次。

| 私有台账 | 主要内容 | 与当前系统衔接 |
|---|---|---|
| 运输需求台账 | 未预约任务、货量、期限、业务粗分类 | 本地派生未来时段运输与资源需求，不产生实际入园事件 |
| 运力承诺台账 | 分类运力、可调整范围、占用与承诺版本 | 扩展当前预约计划，防止同一运力重复申报 |
| 行程经营台账 | 装载、空驶、能源和成本事实 | 在企业本地关联实际车次，未发生的值不得作为事实 |
| 资源需求台账 | 装卸、设备和补能需求 | 与园区版本化的分类容量比较 |
| 履约异常台账 | 原承诺、实际结果、取消或异常类别 | 同一批次本地关联后汇总，保留更正与来源版本 |

私有明细默认由企业侧控制，具备来源记录、采集时间、适用业务时间、单位、完整性与估算标志。更正发布新版本，不改写已签名任务使用的旧快照。

公开目录只列可用字段、单位、允许操作和不泄露业务明细的覆盖信息；企业级精确覆盖数量也需评估敏感性，不能因称为“目录”就自动公开。

## 6. 协议能力分层

| 能力层 | 适用功能 | 需要的改动 |
|---|---|---|
| 本地派生后安全聚合 | 货量、空驶、充电、资源需求总量，成本总量及明确允许公开分子分母的比值 | 扩展类型、校验、分组、投影、指标单位、输出契约及日志脱敏；不能只给表单加字段 |
| 分布与分位数 | 等待、装载、成本或充电需求的分桶计数与近似分位数 | 公共分桶规则、本地分桶、计数聚合和发布限制；精确分位数不能用均值替代 |
| 隐藏中间量的判断与分配 | 只公开容量是否足够、每方获配量，而不恢复精确总需求或成本 | 需要安全比较、适当的算术和分配协议；当前先恢复总量再判断的方式不能满足 |
| 跨企业或跨系统隐私关联 | 同一运输任务、客户或车次在不同数据持有者之间关联 | 需要隐私集合求交（Private Set Intersection，PSI）或隐私关联协议；仅分享标识或对车牌做普通哈希不等于完成关联保护 |

当前实现会恢复计算指标用到的计数、总和等充分统计量。如果只批准公开比值、不允许恢复分子分母，需要先调整协议，不能只在页面中隐藏总量。

## 7. 谁能看到结果

| 接收方 | 默认允许内容 |
|---|---|
| 承运商本方 | 本方明细、本方校验结果、获授权的联合结果和本方确认事项 |
| 园区运营人员 | 完成资源安排所需的批准联合结果及完整性说明；不默认获得每家原始值 |
| 其他承运商 | 不自动接收竞争方明细、单家汇总、园区看到的全部联合结果或完整报价 |
| LLM Agent | 受控公开目录、已批准结果、来源与有效范围说明；不接收私有台账、全部份额或私钥 |
| Git诊断日志 | 事件、任务关联、版本摘要、错误代码和允许公开的元数据；不存原始经营数据或秘密材料 |

是否发布精确总量、区间、比例、缺口或建议，必须在计算前声明。公布联合结果也可能泄露信息，例如三家总量减去两家已知值可推出第三家。提高份额门限不能消除这类结果推断。

建议同时控制最少有效样本、实际贡献方数量、单方占比、最细分组、重叠窗口、连续版本差分和跨会话历史查询。稀疏分组可合并为较粗区间或停止发布；规则按具体数据与接收方确定，不能把某个固定门槛称为充分隐私保证。

执行节点必须事先接受输出范围及结果接收方。若平台不能看到未达发布条件的精确结果，发布条件也需要在安全计算中判断，不能先交给平台再做页面过滤。

## 8. 与当前部署的边界

当前已提供园区与三家企业统一服务、账号登录、数据目录及私钥分区。各企业只保存本方私有经营台账；园区通过 TLS 1.3 双向认证和签名消息取得目录、委派计算并接收批准结果。独立园区端拒绝企业私有材料接口。旧 runtime-ts 仅作迁移归档，不能作为新企业部署包分发。

部署到实际组织时只交付本端密钥目录，并完成跨主机、时钟、采集真实性及结果发布规则验收。本批冻结来源版本、限定接收方并保留范围声明；尚未实现针对稀疏分组或连续差分的更强发布协议，完整声明不能代替隐私门槛。

现有一次多项式的数学恢复门限为两份，执行器要求三个节点全部参与。不能据此宣称抵抗两方串通、支持节点离线或抵抗恶意计算。签名和来源凭证支持来源核对，但不自动证明企业没有漏报、虚报。

模型继续负责理解、规划和解释，受控代码负责权限、数值范围、时间口径、份额计算、输出与审计。主智能体长期记忆仅保存批准摘要及版本、时间和适用范围，并纳入累计查询风险控制。

## 9. 推荐实施顺序

1. **前置改进：**企业账号和数据分区隔离、结果接收方授权、发布规则、来源与版本管理。实验演示和真实业务使用分开。
2. **第一批业务：**未预约需求与到达弹性、实际装载与空驶、分时充电需求。先支持有限的联合总量和明确口径比例；弹性仅统计规模，不自动承诺分配。
3. **第二批业务：**分类运力与专用资源、历史成本和履约异常，增加受控分类及分布统计。成本结果限定用途和接收方。
4. **后续协议：**业务确有需要时，再建设隐藏中间量的比较、私密分配、隐私关联和更强安全模型；不以增加LLM Agent替代协议实现。

每批验收都需要能说明：原始数据由谁控制、哪些量被恢复、谁能看到输出、缺失或拒绝时如何展示，以及使用者能据此作出什么决定。

## 10. 设计完成后的提问示例

本节保留长期目标示例，其中任意货类分组、单车私密安排及跨域关联仍未实现。当前已经支持的第一批提问以[经营台账说明](business.md)和 README 为准。

- “汇总明天东入口尚未预约、且最晚需在中午前到达的运输需求，按两小时给出车次和作业资源压力，不公开各家订单量。”
- “统计过去七天同类货车的联合装载利用率与空驶率，说明有效车次和缺失情况，不列出单家承运商结果。”
- “未来六小时园区需要准备多少充电电量？按已申报需求说明紧迫程度和接口需求，不公开单车剩余电量。”
- “统计上周同一承诺批次的兑现率与取消率，区分计划、实际和补录，不展示企业排名。”
- “在各方不公开精确需求和成本的条件下，只给出经授权的可接纳判断。”（需要新增隐藏中间量的安全比较。）
