# VECTRA 2.0.0 独立部署架构

园区端与企业端分别部署，企业端使用同一HTTP端口，通过不同账号固定绑定不同公司。一个企业Bun进程承载三个公司数据/计算上下文，各公司密钥与台账分目录保存。操作步骤见[README](../README.md)，网络配置见[分端部署](deployment.md)，经营口径见[经营台账](business.md)。

~~~mermaid

  PU[园区 Vue 界面] --> P[园区 Bun API / 登录与权限]
  P --> M[园区协调 Agent]

  M --> Planner[统计规划 Agent / 独立 LLM]
~~~

## 登录、权限与密钥

PortalAuth 使用Argon2id哈希和仅保存令牌摘要的12小时会话。园区与企业使用不同Cookie；企业统一入口的账号在持久绑定表中映射到公司，由会话选择对应上下文。浏览器接口先验证登录与同源，再验证企业固定身份；X-Carrier-Role 只在本企业登录之后表达本方操作范围，不能用请求正文切换成其他公司。园区部署拒绝企业写接口、原始车次/采样编辑接口及完整私有材料接口；企业拒绝园区 Agent 管理和其他公司的读取。

Security 在运行时验证已分发的公开登记表与证书。园区持有 coordinator/planner/analyst/rsu/report 的私钥；公司 A/B/C 分别只持有自己的签名、TLS 和输入密钥，各有独立存储密钥。企业端不持有 CA 或其他组织私钥。初始化工具离线分发；运行数据、凭据、PKI 和数据库不进入 Git。

企业建档、临时车次及历史导入中的新车牌，先通过认证连接登记园区车牌归属摘要，事务拒绝跨企业冲突。该摘要用于所有权唯一约束，不能将它称为隐私集合求交。园区车辆概览通过单独授权接口读取公开档案与最新状态，不包含经营台账。

## 来源与业务数据

ParkData、FleetData、ReservationData 根据部署限定 owners；公司上下文只访问本方加密文件，园区实例 owners 为空，不需要也不能读取企业输入密钥。车牌统一标识车辆，车次按 visitId 单独管理，实际入口仅属于车次。

实际生命周期为排队待入园、入园、开始作业、结束作业、离园。每次默认采用服务端当前上海时间；不得伪造未来实绩，未知事件不补齐。链路的备车就绪、运输发车、园外集结等端点用于九环节共同样本瓶颈分析。预约与未来经营申报不产生实际车次。

BusinessData 按 demand/haulage/returns/charging 保存不可变版本。records.enc.json 使用企业 input.key、AES-GCM 和绑定所有者/类型/版本的 AAD。目录包含字段、公开数量/日期和声明范围；数据由所属公司 API 读取，原始数组不进入跨端 RPC 或模型上下文。

- demand：需求、预约、最低保留与到达窗口；派生未预约、可调整、可提前/延后和紧迫规模，按计划到达或最晚到达选取。
- haulage：关联本方已离园车次与冻结源版本，派生重量/体积/托盘利用率、成对里程及吨公里参考值；按离园时间选取。
- returns：开始、截止、粗区域和车次额度；不公开具体订单或自动匹配。
- charging：本方车辆、电池与电量在本地派生所需电量及接口/紧迫性；未知功率不补零，同车重叠窗口拒绝。

每域每公司最多6000条。未来起点按半小时登记，已开始记录只读，结束可归档，历史版本保留。声明覆盖完整分组才算一家资料齐全；空台账的明确为零与未声明、可选字段缺失分开处理。原始资料仍是企业申报，密码检查不证明内容真实。

## 冻结任务与分布式计算

FederatedPark 先同步公共名称，读取三家已签名目录；FederationManifest 冻结每家来源版本、目录摘要、园区设置及所用容量版本。联合版本由这些内容的摘要确定，保存后不改写。主智能体将查询、来源清单、园区/业务上下文、有效期与参与者统一签名。

FederationTransport 使用 Bun.listen/Bun.connect 原生套接字的 TLS 1.3 双向证书认证与登记指纹固定绑定。端点为 tls://主机:端口，不是 HTTP。JSON 行报文绑定签署者、接收方、用途、唯一 nonce、有效期；响应含请求摘要与签名，错误响应同样认证。请求最多512KiB、响应最多2MiB。连接异常不自动重放工具或计算。

各 FederatedParty 独立验签、核对本地冻结版本与目录摘要，再本地筛选、比较、去重、派生指标和可加充分统计量。每指标分享有效数量、和、平方和、分母；实际车次另有4个覆盖分量，预约2个，经营3个。经营分组含记录数、有记录公司数、声明完整公司数。最多128组、2048分量。

每个分量在有限域2^127−1上独立随机生成一次 Shamir 多项式。每方保留自己位置的份额，向其他两家发送对应份额，共六个输入向量；B/C将本地聚合向量送到指定重构方 A，共两个聚合向量。A 收齐三个点、核对线性关系后重构联合统计量，并签署结果。园区只得到批准结果、公钥/签名与进度计数，不得到输入份额。

数学重构门限为2，当前执行要求三方全员参与，不支持节点掉线容错。两方串通可恢复所持有的输入统计量；线性关系和签名不证明恶意安全或输入真实性。联合充分统计量由 A 恢复，当前输出政策允许其看到这些联合量。少样本、重叠查询和多方合谋可通过结果推断信息，未实现差分隐私或隐藏联合中间量的判断/分配。

园区验证结果签名、完整查询、每家来源清单、全部业务上下文及结果结构。均值、阈值比例和总和比值由确定性代码计算；比值只采用同批字段齐全记录。三家完整空台账可输出零总量，可选字段均缺失时仍输出未知。

充电容量按入口、半小时、接口维护，冻结到业务上下文；容量不得超过接口数量×功率×0.5小时。完整资料和完整半小时边界、容量齐全时才计算电量缺口。需求按申报开始归组，结果是批次电量压力，不是逐车充电安排。

## 多 Agent、报告与消息

三个实际 LLM Agent 均独立配置模型、上下文和受限工具；主智能体委派规划和运营分析，子智能体无长期记忆。模型读取公开目录、批准结果及审计证据，不读取企业原始台账。受控统计 DSL 不包含 SQL、JavaScript 或可执行代码，单次查询不能任意跨域关联。

统计任务必须实际交付规划、计算、分析和签名报告，工具失败不以模型总结代替完成。Agent 采用签名委派与产物回执，运营分析先查询经过校验的审计，再提交结构化事实、假设、建议与边界。计划类历史记忆明确标记为申报结果，不能代替当前查询。

对话卡片按八阶段展示登记身份、上海真实时间、安全协议目的及公开核验材料。园区 SSE 仅发布公开步骤，新部署丢弃 privateDetails，完整私有材料读取一律拒绝。历史对话与报告保留原时刻事实，不能用当前企业证书冒充旧报文凭据。

报告由园区 report 身份签署，绑定请求、计划、批准结果、分析与证据。数据库使用 SQLite WAL，追加事件用于 SSE 和恢复；诊断日志按各端独立路径脱敏。删除对话会取消关联执行并清理应用数据及 Agent 运行记录，主智能体记忆完全不参与删除，审计与 Git 日志继续保留。

## 实现入口与验证范围

| 文件 | 职责 |
|---|---|
| apps/carrier/src/portal.ts、index.ts | 统一企业HTTP入口、账号绑定、公司上下文与本方资料API |
| apps/server/src/index.ts、service.ts | 园区登录、编排、输出与报告 |
| apps/server/src/provision.ts、deployment.ts | 离线迁移、密钥分发与配置校验 |
| apps/server/src/federation-transport.ts | 双向 TLS、签名消息、回应绑定与重放检查 |
| apps/server/src/federation-party.ts、federation-park.ts | 独立企业计算与园区调度 |
| packages/shared/src/business.ts、apps/server/src/business.ts | 四域契约、校验、本地派生与容量 |
| apps/web/src/components/PortalGate.vue、CarrierShell.vue | 独立登录与企业侧栏 |
| BusinessLedgerEditor.vue、BusinessResult.vue、BusinessOperations.vue | 台账、业务结果与分析问题准备 |
| apps/server/tests/federation.test.ts | 真实跨服务 TLS/Shamir、权限、全批指标、报告与迁移 |

隔离检查使用本机不同数据目录与监听端口，实际执行 TLS、Ed25519、Shamir、SQLite 和报告链路，LLM 响应使用可控夹具。它不能代替不同主机、防火墙、代理、外部模型、真实采集或现场业务验收。旧单体工作进程执行器保留供存量协议回归检查；正常 start/dev 只启动园区端与企业统一入口。企业内三个计算上下文共享宿主机，不等于三个组织独立控制数据与密钥。

统一企业入口使用 companies/accounts.sqlite3 保存账号与公司绑定，节点自身不监听HTTP端口；内部TLS端点用于协议协作。账号改变后的响应含 X-Company-Identity，浏览器拒绝把另一公司响应放入当前公司页面。企业账户持有人受API范围控制，企业服务管理员仍掌控全部分区文件及进程。
