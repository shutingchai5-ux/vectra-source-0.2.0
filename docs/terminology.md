# 系统术语与登记身份

本文与共享术语定义 terms.ts、登记身份定义 identities.ts 对齐。界面、模型回答、流程说明和文档使用同一套名称。一个登记身份只有一个显示名称；编号用于核对协议身份，职责和算法不会额外生成角色。

## 登记身份

| 登记编号 | 统一显示名称 | 是否调用大模型 | 实际职责 |
|---|---|---|---|
| coordinator | 园区协调 Agent | 是 | 主智能体：管理长期记忆、委派规划与分析、调度联合计算、复核与最终交付 |
| planner | 统计规划 Agent | 是 | 子智能体：使用自己的模型明确统计范围，提交受约束的方案；不持有长期记忆 |
| analyst | 运营分析 Agent | 是 | 子智能体：使用自己的模型查询证据并提交分析；不持有长期记忆 |
| rsu | 安全授权服务 | 否 | 接收签名任务，核对身份、签名、范围、有效期和重复消息，签发授权回执 |
| carrier-a | 该承运商名称＋协作节点 | 否 | 处理本方数据、计算本地统计量、交换秘密份额，并负责重构及签署批准统计结果 |
| carrier-b | 该承运商名称＋协作节点 | 否 | 处理本方数据、计算本地统计量、交换秘密份额并提交聚合份额 |
| carrier-c | 该承运商名称＋协作节点 | 否 | 处理本方数据、计算本地统计量、交换秘密份额并提交聚合份额 |
| report | 签名报告服务 | 否 | 整理签名报告、签名及验签、加密保存并交付 |

共有三个调用大模型的 Agent，各有独立职责、任务上下文与工具边界，可以分别配置模型。长期记忆仅由园区协调 Agent 持有，子智能体只接收主智能体随本次委派提供的必要背景。承担重构的 carrier-a 仍使用原登记名称，不另称“重构者”或另设角色。

rsu 是安全授权服务的登记编号，证书和协议使用该编号。它在本系统中是一项后端服务，不能据此声称现场部署了实体路侧设备。

TLS、mTLS、Ed25519、X.509、Shamir、AES-256-GCM、JCS、SHA-256 是协议、算法或标准名称，用于说明执行方法，不作为参与角色。CA 表示证书颁发机构，在本项目中是本地证书信任根，也不是额外的对话角色。

## 两种曾被混称为“网关”的对象

- **安全授权服务**：系统内部的任务授权主体。授权回执表示本次任务通过授权检查，后面仍需完成联合计算、证据分析和报告交付。
- **模型服务接口**：外部模型服务的访问地址和兼容参数。各 Agent 通过各自配置的接口调用模型；它不是系统新增的登记身份，也不承担任务安全授权。

## 业务与协议术语

| 统一术语 | 含义 |
|---|---|
| 承运商 | 持有本方车辆和车次数据的企业，编号为 carrier-a/b/c |
| 承运商协作节点 | 代表一家承运商执行确定性数据处理和秘密分享的程序；一个节点可处理多辆车辆，不等于一辆车 |
| 车辆 | 以规范化后的完整车牌号唯一识别的实际车辆；车辆数量与承运商协作节点数量分别统计 |
| 车辆档案 | 车牌号、归属、车型、动力、载重及通行入口等基础资料 |
| 车牌号 | 车辆的唯一业务标识；按“省份简称＋发牌机关字母＋剩余号码”录入，统一为大写且不含空格或分隔点。同一车牌不能重复建档或归属不同承运商。导入字段 vehicleId 也填写完整车牌，不另设车辆编号 |
| 承运商角色 | 本机工作台选择的业务操作范围，保存接口校验其角色凭据与资料归属；不额外生成 Agent 或协作节点身份 |
| 车次 | 一次实际进园到离园的业务记录；同车再次进园产生新的车次编号 |
| 入口 | 园区固定的东入口、南入口、西入口、北入口；车辆可登记多个通行入口，单个车次记录一个实际入口 |
| 任务计划 | 一轮用户请求的处理类型、允许范围与必须交付的结果 |
| 统计方案 | 任务中获准执行的入口、时间、车次口径和统计指标 |
| 授权回执 | 安全授权服务签发的授权结果，绑定本次任务、请求和消息；不表示统计或报告完成 |
| 份额接收回执 | 承运商协作节点在认证连接中确认收到份额；不同于授权回执，不据此声称存在独立数字签名 |
| 秘密份额 | 用于联合计算的随机数据分量，依据秘密分享方案生成；不同于车辆原始记录 |
| 聚合份额 | 一个承运商协作节点对同一位置收到的秘密份额求和后形成的数据，供批准统计结果重构使用 |
| 批准统计结果 | 实际联合计算并通过来源与范围检查的统计值及覆盖信息 |
| 签名报告 | 包含任务、批准统计结果、分析、总结及数字签名的交付文件；“签名报告服务”是生成它的主体 |
| 验证报告签名 | 检查登记签署者、内容完整性与任务绑定，不证明原始事件真实或运营建议正确 |
| 数据版本 | 一次保存后形成的完整数据版本；新任务冻结版本，历史报告仍引用原版本 |
| 完整协议材料 | 实际记录的证书、报文、密钥、原始输入与秘密份额等本机材料 |
| 审计记录 | 用于追溯任务和安全操作的完整性链记录 |
| 诊断日志 | 用于排查错误的脱敏对话日志与操作日志，不替代审计记录或签名报告 |

当前业务统一称“入口”。历史采样接口中的 road 可表示采样路段，原始历史字段按原协议解释，不作为第五个园区入口。

## 页面名称

页面固定使用：**AI 对话、Agent 工作组、Agent 详情、园区车辆、承运商工作台、证据与审计、签名报告**。承运商工作台包含车辆档案与车次登记，顶部切换本机承运商角色；归属固定为当前角色。模型配置统一位于 Agent 详情的“底层模型”。报告的检查操作统一称“验证报告签名”。

## 历史称呼的读取规则

| 历史称呼 | 统一归属 |
|---|---|
| 任务管家、任务协调器、协调方、协调端、计算助手、执行器 | 园区协调 Agent |
| 信息安全分析 Agent、运营分析师、园区运营分析员 | 运营分析 Agent |
| 网关、安全网关、路侧安全网关、路侧卫士、RSU、路侧单元 | 安全授权服务 |
| 报告专员、报告服务、报告验证服务 | 签名报告服务 |
| 模型网关、自定义网关 | 模型服务接口 |

旧称只用于识别历史记录，新的执行消息使用登记编号。可读说明将旧称归到对应身份；原始签名报文、证书、代码、链接、数学公式和用户输入保留原文，避免改变证据或用户表达。用户配置的园区及承运商名称也保持原样。
