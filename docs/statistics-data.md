# 按日期填充统计数据

`scripts/populate-statistics.ts` 为现有独立部署追加一个上海日期的数据，保留原记录和历史版本，不添加额外的数据标记。三个企业分别保存本方车辆、车次、预约和四类经营台账；园区保存入口、作业与充电容量。

```powershell
# 只在隔离副本中校验，不切换运行中的台账版本
bun scripts/populate-statistics.ts --date 2026-11-05 --allow-future-events

# 校验通过后直接写入当前 runtime-deploy 部署
bun scripts/populate-statistics.ts --date 2026-11-05 --allow-future-events --apply
```

未来日期的实际车次需要显式指定 `--allow-future-events`，仅离线填充使用日期结束时刻校验事件顺序。发布元数据使用真实服务器时间；浏览器接口和实际统计的未来时间限制继续生效。计划类统计可立即使用对应日期，实际车次统计仍须等真实时间到达相应区间。

每家新增32辆车、100个车次（84已离园、16未离园）、192条预约、192条运输需求、84条装载空驶事实、192条回程、192条充电请求。园区新增192条入口/作业半小时容量、576条分接口充电容量，覆盖全天四个入口。台账资料完整范围为指定日期的上海零点至次日零点。

数据包括重复进园与车辆去重、排队/入园/作业中/作业完成/离园/暂无车次、预约准点/提前/迟到/缺失、完整和缺少端点的链路、零与缺失的里程或用电、不同装载利用率与空驶比例、可提前/延后/固定需求、九个回程区域、三种充电接口、紧迫/功率不足/未知功率请求，以及充足/不足/明确为零的容量。

填充前在独立副本校验全部来源关联与字段，并执行25套查询，覆盖到达、离园、全链路瓶颈、预约协调、四类经营统计、按最晚到达选取、各回程区域，以及所有支持字段的求和、均值、总体方差、标准差和各类总量比值。三方加密存储保持独立，装载记录绑定实际发布的本方车次版本。载货与空驶里程在来源总里程已记录时严格相符。

重复运行不会追加相同编号；发现同编号内容冲突会停止，已有同入口时段的预约或容量会保留。写入前复核当前版本，并保存原目录指针与统计基线到 `runtime-deploy/backups/statistics-日期-时间戳`。版本切换发生错误会恢复已切换的目录指针，原始不可变版本继续保留。
