# VECTRA

**面向车联网的多智能体可信数据协作与隐私保护系统 · v1.0.3**

通过自然语言提出车辆数据统计需求，查看每个角色的执行过程，并获取签名报告。适用于本机课程展示、协议学习与协作开发。

[GitHub 仓库](https://github.com/shutingchai5-ux/vectra-source-0.2.0) · [架构说明](docs/architecture.md) · [日志说明](logs/README.md)

## 可以做什么

- 自行配置车辆数量，新增、编辑或导入带时间的车辆数据。
- 按路段和时间范围统计平均速度、车辆数、样本数、速度波动、停车样本比例、里程和能耗。
- 在同一对话中继续追问、调查证据或验证报告。
- 查看不同角色的独立消息，以及每条消息所属的八阶段、涉及的安全协议和协议作用。
- 阅读排版后的数学公式，按需展开报文、签名、密钥与原始数据。
- 在左侧管理历史对话，下载签名报告，使用日志排查错误。

所有页面与日志日期按**中国上海时间（UTC+8）**显示。统计基于用户提供的数据；新安装不生成车辆样本，也不会自动采集外部道路信息。

## 开始使用

### 1. 获取项目与安装依赖

准备好 **Git** 和 **Bun 1.4.3 或更新版本**，从 GitHub 克隆项目：

```powershell
git clone https://github.com/shutingchai5-ux/vectra-source-0.2.0.git
Set-Location vectra-source-0.2.0
```

切换到团队约定的开发分支。以下命令在包含 `package.json` 的目录执行；本文对应 v1.0.3 的 TypeScript 版本。

```powershell
bun install --frozen-lockfile
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
bun run dev
```

打开 [本地工作台](http://127.0.0.1:5173)。开发时修改前端会即时更新，修改后端会自动重启；已有会话和数据继续保留。停止服务时在启动终端按 **Ctrl+C**。

### 2. 配置模型服务

在左侧打开 **模型设置**，填写支持 Chat Completions 工具调用的服务地址、模型名称与 API Key，保存后返回对话页。

已保存配置默认只读，点击“修改配置”后才能调整；保存后重新锁定，取消修改会恢复原值。可选择是否开启深度思考，自定义网关可指定 DeepSeek、通义千问或 OpenAI 兼容方式。所选模型需支持对应模式与工具调用；调整只影响后续新任务，内部推理不显示或写入日志。

系统统一使用配置的模型服务。尚未配置时可以编辑车辆数据，但不能发起对话；模型调用失败会显示错误，不切换到演示回答。

### 3. 准备车辆数据

在左侧打开 **车辆数据**，选择一种方式：

- **直接编辑**：填写新增车辆数量、路段和速度，点击“新增车辆”，检查采样时间及每行数据，再点击“保存并发布完整数据”。
- **编辑已有数据**：先点击“载入当前数据编辑”，再增加车辆、追加采样或删除记录，最后保存。
- **导入 JSON**：提供记录数组。必填字段为 `vehicleId`、`road`、`recordedAt`、`speed`；里程 `distanceKm` 与能耗 `energyKwh` 可选。

同一辆车的多次采样使用相同车辆编号。采样时间按上海时间理解；里程和能耗填写**采样区间增量**。计算节点可自动分配，三个计算节点不代表只能有三辆车。

编辑草稿不会立即改变数据；保存会发布完整新快照。单次最多 6000 条记录、2 MiB。已有任务继续使用原来的数据版本。

### 4. 发起对话

返回 **AI 对话**，直接输入问题，或点击输入框上方的“猜你想问”后修改发送。

首次可以尝试：

> 统计 S101 路段过去 60 秒的平均速度，保护车辆输入并生成签名报告。

**先检查采样时间。**“过去 60 秒”使用提问时的实际时间范围。如果数据是历史记录，请明确指定日期与起止时间；窗口没有样本时会显示无数据。

“今天”按上海零点至本次提问时间统计；“昨天”“前天”按相应完整自然日统计。明确指定的小时范围会保留，未来时段与超过 31 天的范围会被拒绝。

其他示例：

| 想了解什么 | 可以这样问 |
|---|---|
| 多路段比较 | 分别统计 S101、S102 过去 10 分钟的平均速度、车辆数和样本数。 |
| 低速情况 | 统计 S101 过去 15 分钟速度低于 20 km/h 的样本占比。 |
| 里程与能耗 | 统计 S101 过去一小时的总里程、总能耗和每百公里能耗。 |
| 继续解释 | 解释上一轮统计结果，并说明有哪些不确定性。 |
| 验证结果 | 验证当前对话最近一份报告的签名。 |

路段必须已经导入；查询最多覆盖 8 个路段、12 个指标和 31 天。当前支持受控指标组合，不支持中位数、分位数、任意公式或自动查询外部道路。平均速度按有效样本计算，样本比例不等于持续时间比例。

输入框使用 **Enter 发送、Shift + Enter 换行**。识别不符合预期时，可在输入框下方明确选择任务类型。

### 5. 阅读过程与获取结果

每条角色消息标注“阶段 N/8”，与项目流程说明一致：

**请求受理 → 查询规划 → 签名授权 → 节点准备 → 份额交换 → 输出重构 → 证据分析 → 报告交付**

每张卡片会用易读说明介绍当前操作、为什么需要这一步及接下来的安排；涉及的安全机制会标注缩写、全称与本步用途。展开“执行经过”可阅读具体处理方式，计算公式直接排版显示。需要逐字核对时，展开“协议、报文与校验数据”或“密钥、原始数据与完整份额”，查看实际数据或复制原文；阅读说明不会改写已保存的报文、签名与历史记录。

卡片时间按各自的实际记录显示，统一使用上海时区并精确到毫秒；持续执行的步骤分别显示开始和完成／更新时间。统计、分析、验证与最终交付使用各自的保存时间。旧对话优先从历史事件中读取记录时间；没有可靠时间的项目会注明未记录，不补造时间。

统计结果、证据分析与最终交付分别展示。只有本轮显示**已完成**，才代表所需产物和报告已经成功交付；中途得到统计值不代表整轮成功。完成后可打开签名报告，下载或再次验签。

在左侧打开历史记录可以继续追问。删除对话会先取消关联任务，再清理会话及报告；已保留的 Git 诊断日志与安全审计不会一并删除。

“证据与审计”分为**分类事件、证据分析、审计校验**。事件按任务执行、数据管理、身份与安全、隐私计算、报告交付和系统运行分类，可按任务、关键词及失败 / 拒绝结果筛选；展开详情可查看原始记录与哈希。分类统计覆盖最近 100 条已加载事件，完整审计链校验独立检查全部记录。

## 通过 GitHub 协作

项目使用 GitHub 管理代码、问题和 Pull Request。建议一次分支只处理一个明确问题：

1. 在 Issue 中说明目标、复现步骤或预期行为，确认团队使用的目标分支。
2. 切换到该分支并同步，再创建功能分支：
   ```powershell
   git pull --ff-only
   git switch -c feature/message-display
   ```
3. 使用 `bun run dev` 开发。修改依赖时一起更新 `package.json` 与 `bun.lock`；界面或使用方式变化时同步更新 README。
4. 提交前执行 `bun run check`。涉及任务、安全或存储逻辑时，再运行对应测试；无需为每次文案修改重复完整测试。
5. 检查 `git status`，只暂存本次修改，提交并推送功能分支，在 GitHub 发起 Pull Request。PR 说明解决的问题、主要变化及实际验证范围。
6. 根据评审意见调整，通过仓库的 GitHub Actions 检查后，由团队评审合并。

**提交范围：**源码、配置模板、文档、锁文件，以及按项目要求保留的脱敏 `logs/`。`.env`、`runtime-ts/`、数据库、密钥、依赖与构建目录不提交。日志不会自动提交或推送。

Codex 辅助脚本和检查记录统一放在仓库外的同级 `codex_files/`，不作为项目源码或运行依赖。

## 运行已有构建

不需要开发热更新时：

```powershell
bun run build
bun run start
```

打开 [运行工作台](http://127.0.0.1:8000)。停止时按 **Ctrl+C**，也可在另一个终端执行 `bun run stop`。开发热更新与生产环境无中断发布是不同功能。

常用命令：

| 命令 | 用途 |
|---|---|
| `bun run dev` | 启动前后端开发热更新 |
| `bun run check` | 类型检查与生产构建 |
| `bun test apps/server/tests/具体文件.test.ts` | 检查受影响的核心功能 |
| `bun run build` / `bun run start` | 构建并运行 |
| `bun run stop` | 停止当前实例 |
| `bun run package` | 生成源码分发包 |

## 遇到问题

| 现象 | 优先检查 |
|---|---|
| 无法发送消息 | 模型设置是否完整、服务是否支持工具调用 |
| 路段不存在或没有数据 | 是否保存发布、路段名称是否一致、查询区间是否覆盖采样时间 |
| 编辑后没有生效 | 是否点击“保存并发布完整数据”；版本冲突时重新载入再编辑 |
| 模型或任务执行失败 | 查看失败消息和阶段，再按 taskId、conversationId 或 requestId 查日志 |
| 热更新后断线 | 等待自动重连；重启前未完成的任务不会自动重做 |
| 页面仍显示旧版本 | 开发模式刷新页面；构建运行模式重新执行 build 后启动 |

对话日志位于 `logs/conversations/`，操作日志位于 `logs/operations/`，格式和排查方法见[日志说明](logs/README.md)。

## 项目说明

当前使用 **Vue 3 + TypeScript + Effect + Vite**，后端为 **Bun + TypeScript + SQLite**。权限、密码运算、统计和报告发布条件由代码执行，模型负责规划、工具调用和解释。架构、协议与数据边界见[架构说明](docs/architecture.md)。

本项目用于本机教学与开发。完整材料展示会向本机观察者开放私钥和原始输入；签名不能证明数据来源真实。本仓库尚未声明项目许可证，第三方依赖保留各自许可证。
